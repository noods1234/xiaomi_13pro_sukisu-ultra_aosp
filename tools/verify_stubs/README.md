# verify_stubs — hand-written stand-ins used ONLY by tools/verify_compile.sh

These are **not** production code and are never compiled into the app. They exist because two
categories of type are unavailable offline:

- `androidx/**` — androidx is published to Google Maven, which is unreachable in this environment.
- `R.kt`, `ActivityHomeBinding.kt` — normally generated by the Android Gradle Plugin from
  `res/` at build time.

**Evidence caveat:** a stub with a wrong signature can mask a real compile error. Classes verified
only against these stubs (tier 3) are therefore reported as *plausible*, not *verified*. Tier 2
(real `android-all` framework classes) and tier 1 (pure JVM, executed tests) are the strong tiers.

If androidx ever becomes reachable, delete the `androidx/` stubs and add the real artifacts.
